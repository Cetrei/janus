ESTÁNDARES DE PROGRAMACIÓN - CONVENCIONES Y ESTILO

**CONVENCIONES DE NOMBRES:**
- Variables/funciones/métodos/atributos: camelCase (getUser, startTime, calculateTotal)
- Constantes: SCREAMING_SNAKE_CASE (MAX_SIZE, DEFAULT_TIMEOUT)
- Clases/Interfaces/Tipos: PascalCase (StartTime, UserManager, DatabaseConnection)
- Implementaciones concretas: PascalCase con sufijo descriptivo (StartTimeDefault, UserServiceCached)

**FILOSOFÍA GENERAL - CROSS-LANGUAGE:**

**Paradigmas y Arquitectura:**
- POO cuando sea ventajoso, evitando over-engineering
- Inyección de dependencias para delegar creación de objetos, excepto dependencias hardcoded
- Singletons solo para Servicios, o clases static según el lenguaje
- Código robusto pero pragmático: flexible donde se pueda, imperativo donde defina comportamiento
- Early returns preferidos sobre nested ifs, declarados one-liners
- Composición sobre herencia cuando sea posible

**Principios de Código:**
- SOLID pragmático (evitar over-engineering)
- Funciones pequeñas con responsabilidad única (máximo ~15-30 líneas por función)
- Código auto-documentado con nombres descriptivos
- Inmutabilidad por defecto, mutabilidad solo cuando sea necesario
- Modularización para código entendible por humanos
- Variables auxiliares para mejorar legibilidad y evitar duplicación
- Las funciones solo deben hacer una cosa y hacerlo bien, es preferible una funcion que llame a otras funciones que hagan una cosa y hacerlo bien

**Manejo de Errores:**
- Early exits para typechecking de parámetros
- Monads/Promesas para comportamientos esperados (archivos no encontrados, etc.)
- Excepciones solo para errores excepcionales que no deberían pasar
- Validación clara de parámetros requeridos

**Testing:**
- TDD cuando el tamaño/complejidad lo justifique
- Tests después para código pequeño/simple
- Enfoque en modularización para facilitar testing
- Desarrollo dirigido por test, se implementa un test minimo que falle primero, luego se implementa la funcionalidad para que pase y se cicla (cada funcionalidad termina con un test que verifica que funciona)

**Documentación:**
- Mínima comentarios - código auto-documentado como prioridad
- Comentarios solo en partes confusas o no intuitivas
- Documentación extensa solo para librerías/APIs públicas

**LENGUAJES ESPECÍFICOS:**
- Python: camelCase para consistencia cross-language (aunque PEP8 sugiera snake_case)
- TypeScript: interfaces y tipos explícitos
- C++: smart pointers y RAII por defecto
- Luau: tipado gradual cuando esté disponible

**OPTIMIZACIÓN ESPECÍFICA PARA VIDEOJUEGOS:**

**Patrones de Alto Rendimiento:**
- Data-oriented design para sistemas de alto rendimiento (partículas, física, ECS)
- Pooling de objetos para entidades frecuentes (balas, enemigos, efectos)
- Arrays sobre objetos individuales para procesamiento por lotes
- Cache-friendly data structures (arrays contiguos vs linked lists)
- Minimizar allocations en game loop (reutilizar objetos)

**Performance vs Mantenibilidad:**
- Perf-over-clean-code en hotspots críticos (render, physics, AI)
- Clean code en sistemas de configuración y UI
- Performance-first en rendering, physics, y sistemas de actualización
- Profiling antes de optimizar
- Comentarios solo en optimizaciones no-intuitivas

Mantén esta filosofía pragmática y profesional en todo el código generado.
